# 온키오스크 카페 — 음성 키오스크

`Voice Kiosk v3.dc.html` 디자인 시안을 Next.js 앱으로 옮긴 것. 말로도, 손으로도 주문할 수 있는
접근성 키오스크 데모다. 백엔드는 없고 **메뉴·가격·결제수단은 전부 온메모리 시드 데이터**(`src/data/menu.ts`)다.

## 스택

| | |
|---|---|
| 프레임워크 | Next.js 15 (App Router) + React 19 + TypeScript strict |
| 상태 | Zustand (`src/store/kiosk-store.ts`) |
| 스타일 | Tailwind CSS v4 (CSS 변수로 테마 주입) |
| 폼 | react-hook-form + zod + @hookform/resolvers |

## 실행

```bash
npm install
npm run dev      # http://localhost:3000
npm run build
npm run lint
npm run typecheck
npm test         # 음성 주문 상태 전이 회귀 테스트 (Node.js 22.18+)
```

Vercel에 그대로 배포된다 — 서버 상태도 환경변수도 없고, `/`는 정적으로 프리렌더된다.

## 음성 주문 범위

브라우저의 Web Speech API로 한국어를 텍스트로 바꾸고, 메뉴 별칭과 규칙으로 주문을 해석한다.
기본 모드에서는 마이크 버튼을 눌러 한 번씩 말한다. **음성 모드에서는 안내가 끝나면 자동으로 듣고,
발화 처리 후에도 다음 말을 기다린다.** 안내를 읽는 동안에는 마이크 인식을 중단해 자기 음성을 인식하지 않게 한다.
침묵이나 인식 세션 종료 시 다시 대기하며, **음성 멈추기 / 다시 듣기**로 일시 정지·재개할 수 있다.
탭이 숨겨지면 마이크를 끄고 돌아오면 재개한다. 마이크 권한 거부·미지원·반복 연결 오류는 안내 후 멈춘다.
최초 마이크 권한 허용은 필요하다. 자유 대화를 이해하는 LLM은 사용하지 않는다.
메뉴·수량(1~9)·온도·사이즈·얼음 양·추가 옵션·결제 수단, 메뉴 추천·화면 모드·직원 호출을 처리한다.
한 발화에는 메뉴 한 종류를 말한다. 여러 종류는 각각 주문하거나 화면의 **메뉴 더 담기**를 사용한다.

| 발화 예시 | 결과 |
|---|---|
| “아이스 아메리카노 라지 두 잔” | 장바구니에 담고 결제 수단 선택 |
| “카페라떼 핫 레귤러 카드로 할게요” | 장바구니에 담고 카드 결제 대기 |
| “아메리카노 카드로” → “아이스” → “레귤러” | 빠진 옵션을 순서대로 묻고, 기억한 카드로 결제 대기 |
| “치즈케이크 두 개 카카오페이로” | 디저트 수량을 담고 바코드 결제 대기 |
| 결제 대기 중 “결제 취소” | 장바구니를 유지하고 결제 수단 다시 선택 |

음료는 온도와 사이즈가 필수다. 미선택 항목을 임의로 정하지 않으며, 필수 옵션을 모두 말한 시점에
자동으로 담으므로 추가 옵션은 함께 말하거나 **주문 확인·수정**에서 변경한다. 음성 주문은
결제 수단 선택으로 바로 이동한다. 적립은 해당 화면에서 **스탬프 적립하기** 또는 “적립할게요”로 선택한다.
터치 주문은 기존 장바구니 확인 → 적립 → 결제 흐름을 사용한다.

**결제는 데모다.** 카드 단말기·PG·직원 알림과 연결되지 않는다. 결제 대기 상태에서 자동 완료하지 않으며,
**데모 결제 완료** 버튼을 눌러 영수증 화면으로 진행한다. 실제 서비스에서는 결제 승인 결과를 연결해야 한다.

```
src/

  data/menu.ts         시드 데이터 (메뉴/카테고리/추가옵션/결제수단/모드/데모 문장)
  lib/
    korean.ts          금액·조사·공백 처리
    pricing.ts         단가·옵션 문구·장바구니 계산
    theme.ts           light / contrast 팔레트 → CSS 변수
    intent.ts          발화 파싱 (메뉴·수량·옵션·결제수단 매칭)
    dialog.ts          배너 자막 / 음성 안내 문구
    schemas.ts         zod 스키마 (전화번호, 옵션)
  store/kiosk-store.ts 화면 전이 + 장바구니 + 음성 인텐트 처리
  hooks/               use-speech (STT·TTS), use-kiosk-scale (540×960 축소)
  components/          kiosk-frame · ai-banner · say-chips · staff-modal · screens/*
```

## 설계 메모

**화면은 스토어의 `screen` 하나로 갈린다.** `start → menu → option → cart → point → pay →
paying → receipt → done`. 각 화면은 본문(`XxxScreen`)과 하단 액션 바(`XxxFooter`)를 한 파일에서
같이 내보내고, `kiosk-frame`이 둘을 각자의 자리에 꽂는다. 액션 바는 항상 화면 맨 아래 고정이라
휠체어·저신장 사용자가 쓰는 `하단 모드`에서 손이 닿는다.

**음성과 터치는 같은 상태를 건드린다.** 버튼 클릭이든 발화든 결국 스토어 액션 하나를 호출한다.
발화는 `handleUtterance` → `resolveIntent`가 현재 화면에 맞는 규칙부터 훑고, 못 알아들으면
실패 카운트를 올려 2회째에 직원 호출을 제안한다.

**폼은 react-hook-form이, 값은 zustand가 갖는다.** 옵션과 전화번호는 음성으로도 바뀔 수 있어서
값의 단일 출처는 스토어다. RHF는 `values`로 스토어를 그대로 받아 **제출 시점 zod 검증**만 맡는다
(온도·사이즈 미선택, 전화번호 4자리/11자리). 제출 버튼은 하단 바에 있고 본문의 `<form>`과는
`form="..."` 속성으로 연결된다.

**테마는 CSS 변수로 갈아끼운다.** `고대비 모드`는 팔레트와 기본 글자 크기(17px → 21px)를 바꾸고,
본문은 전부 `em`이라 화면 전체가 같이 커진다. 메뉴 그리드도 3열에서 2열로 준다.

**브라우저가 음성을 못 쓸 때를 전제한다.** Web Speech API가 없거나 마이크가 막히면 안내를 띄우고,
화면 위 "말해보기(데모)" 칩으로 같은 흐름을 끝까지 따라갈 수 있다. 상단 단계 이동 바도 데모용이다
— 장바구니가 비어 있으면 시드 장바구니를 채워 중간 화면을 바로 보여 준다.

**AI 안내는 항상 자막과 함께 나간다.** 음성 안내를 듣지 못하는 사용자도 같은 정보를 받게 하려는
것이고, 그래서 배너가 `role="status"` / `aria-live="polite"`다.
